# Задача 5. Магические кристаллы (диаметр множества точек)

## Условие кратко

Дано N точек с целыми координатами (N ≤ 200000, |x|, |y| ≤ 10⁹).
Найти максимум величины (xᵢ − xⱼ)² + (yᵢ − yⱼ)² по всем парам различных точек.
Если точка одна — вывести 0.

Это классическая задача «**диаметр множества точек**». Ответ просят в квадрате
специально: корень давал бы дробное число и ошибки округления, а квадрат —
всегда целое, и питон считает его точно (целые числа в питоне неограниченные,
максимум здесь 8·10¹⁸ и он помещается без проблем).

## Файлы

| файл | что это | сложность | на тестах из `Тесты/5` |
|---|---|---|---|
| `5-1.py` | перебор всех пар | O(N²) | 20 из 30 |
| `5-2.py` | выпуклая оболочка + перебор пар её вершин | O(N log N + h²) | 28 из 30 |
| `5-3.py` | выпуклая оболочка + вращающиеся калиперы | O(N log N) | **30 из 30**, максимум 0.37 с |

Три версии сделаны специально: каждая следующая чинит ровно одну проблему
предыдущей. Разбираться проще по порядку.

Тесты лежат в `Тесты/5/Архив (15)`: файл `N` — вход, файл `Na` — правильный ответ.

## Версия 1: перебор всех пар (`5-1.py`)

Два вложенных цикла: берём каждую пару точек, считаем квадрат расстояния,
запоминаем максимум.

```python
best = 0
for i in range(n):
    for j in range(i + 1, n):
        dx = points[i][0] - points[j][0]
        dy = points[i][1] - points[j][1]
        d2 = dx * dx + dy * dy
        if d2 > best:
            best = d2
```

`j` начинается с `i + 1`, чтобы не считать одну и ту же пару дважды и не брать
пару точки с самой собой.

Случай «одна точка» обрабатывается сам собой: внутренний цикл не выполнится ни
разу, `best` останется 0.

**Почему не проходит.** Пар примерно N²/2. Замер: N = 3000 → 0.68 с. Пар растёт
как квадрат, значит для N = 200000 это примерно в 4400 раз дольше — около
**50 минут**.

Но версия всё равно нужна: она заведомо правильная, и ею проверяют быстрые
решения на маленьких случайных тестах.

## Версия 2: выпуклая оболочка (`5-2.py`)

### Главная идея задачи

Представь, что точки — это гвозди в доске, и ты натянул вокруг них резинку.
Резинка ляжет на самые внешние гвозди и образует выпуклый многоугольник — это
**выпуклая оболочка**.

**Ключевой факт: самая далёкая пара всегда лежит на резинке.** Если точка
внутри, её можно сдвинуть наружу и увеличить расстояние — значит внутренняя
точка не может быть рекордсменом. Все внутренние точки можно выбросить.

На практике это выбрасывает почти всё. Замеры на настоящих тестах задачи:

| тест | точек | вершин оболочки |
|---|---|---|
| 21 | 182622 | 31 |
| 22 | 176505 | 11 |
| 25 | 166702 | 15 |
| 30 | 119812 | 29 |

То есть 99.98% точек отпадает.

### Как строится оболочка (алгоритм Эндрю, monotone chain)

Сначала точки сортируются по x (при равном x — по y). Дальше оболочка строится
в две половины, потому что у замкнутого контура нет «начала»:

- **нижняя** цепочка — от самой левой точки до самой правой по низу (идём по
  возрастанию x);
- **верхняя** цепочка — от правой обратно к левой по верху (идём по убыванию x).

Отсюда `for p in points` и `for p in reversed(points)`. Код внутри циклов
**абсолютно одинаковый** — это один алгоритм, запущенный дважды: пройди его
задом наперёд, и низ станет верхом.

### Векторное произведение

```python
def cross(o, a, b):
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])
```

Ты идёшь из `o` в `a`, потом из `a` в `b`. Функция отвечает на один вопрос:
**куда ты повернул в точке `a`**?

- `> 0` — налево (против часовой стрелки);
- `< 0` — направо;
- `= 0` — не поворачивал, три точки на одной прямой.

По модулю это удвоенная площадь треугольника `oab`. Отсюда важное следствие:
при фиксированных `o` и `a` значение `cross` пропорционально **расстоянию от
точки `b` до прямой `oa`** (основание общее, значит площадь пропорциональна
высоте). Это понадобится в калиперах.

### Правило: выпуклая линия поворачивает всегда в одну сторону

Если идти по границе выпуклой фигуры, поворачивать будешь только влево, ни разу
вправо. Встретился поворот вправо — это вмятина, и вершина, в которой ты
повернул вправо, границе не принадлежит.

```python
lower = []
for p in points:
    while len(lower) >= 2 and cross(lower[-2], lower[-1], p) <= 0:
        lower.pop()
    lower.append(p)
```

Читается так: «пока последний поворот не левый — выкидывай последнюю точку,
потом добавляй новую».

- `lower[-2], lower[-1]` — две последние добавленные точки, `p` — новая. Это и
  есть тройка `o, a, b`.
- `len(lower) >= 2` — нужны минимум две точки до новой, иначе поворачивать негде.
- `pop()` выкидывает `lower[-1]` — вершину, в которой поворот оказался неверным.
- `while`, а не `if`: выкинув одну точку, последней становится другая, и поворот
  надо проверить заново. За один шаг может вылететь несколько точек подряд.
- `<= 0`, а не `< 0`: ноль означает «три точки на прямой». Средняя точка на
  прямом участке границы не нужна, поэтому тоже выкидывается. Оболочка выходит
  строго выпуклой — это важно для калиперов, на лишних точках рёбер они могут
  зациклиться.

Это обычный **стек**: каждая точка кладётся ровно один раз и выкидывается
максимум один раз, поэтому весь цикл работает за O(N), несмотря на `while`
внутри `for`.

### Трассировка на 6 точках

```
y
4 │       ●(3,4)
3 │   ●(1,3)
2 │           ●(5,2)
1 │     ●(2,1)
0 │ ●(0,0)   ●(4,0)
  └─────────────────► x
    0 1 2 3 4 5
```

Отсортированные точки: `(0,0), (1,3), (2,1), (3,4), (4,0), (5,2)`

**Нижняя половина (слева направо):**

```
берём (0,0)  стек пуст → [(0,0)]
берём (1,3)  одна точка, проверять нечего → [(0,0), (1,3)]
берём (2,1)  cross((0,0),(1,3),(2,1)) = -5 ≤ 0 → выкидываем (1,3)
             → [(0,0), (2,1)]
берём (3,4)  cross((0,0),(2,1),(3,4)) = 5 > 0 → ок
             → [(0,0), (2,1), (3,4)]
берём (4,0)  cross((2,1),(3,4),(4,0)) = -7 ≤ 0 → выкидываем (3,4)
             cross((0,0),(2,1),(4,0)) = -4 ≤ 0 → выкидываем (2,1)
             → [(0,0), (4,0)]
берём (5,2)  cross((0,0),(4,0),(5,2)) = 8 > 0 → ок
             → [(0,0), (4,0), (5,2)]
```

На шаге `(4,0)` вылетели **две точки подряд** — вот зачем `while`. Точка `(3,4)`
выкинулась здесь, но позже честно попала в верхнюю половину: каждая точка
проверяется в обоих проходах, ничего не теряется.

**Верхняя половина (справа налево):**

```
берём (5,2)  → [(5,2)]
берём (4,0)  → [(5,2), (4,0)]
берём (3,4)  cross((5,2),(4,0),(3,4)) = -6 ≤ 0 → выкидываем (4,0)
             → [(5,2), (3,4)]
берём (2,1)  cross((5,2),(3,4),(2,1)) = 8 > 0 → ок
             → [(5,2), (3,4), (2,1)]
берём (1,3)  cross((3,4),(2,1),(1,3)) = -5 ≤ 0 → выкидываем (2,1)
             cross((5,2),(3,4),(1,3)) = 6 > 0 → ок
             → [(5,2), (3,4), (1,3)]
берём (0,0)  cross((3,4),(1,3),(0,0)) = 5 > 0 → ок
             → [(5,2), (3,4), (1,3), (0,0)]
```

Точка `(2,1)` — единственная, которую выкинуло **в обоих** проходах. Это и
значит «лежит внутри».

### Зачем `[:-1]`

```
lower = [(0,0), (4,0), (5,2)]
upper = [(5,2), (3,4), (1,3), (0,0)]
```

Низ идёт от левой точки к правой, верх — от правой обратно к левой, поэтому
**концы у них общие**: `(5,2)` — последняя в `lower` и первая в `upper`, `(0,0)`
— первая в `lower` и последняя в `upper`. Склеишь как есть — обе крайние точки
задвоятся.

```
lower[:-1] = [(0,0), (4,0)]           ← отрезали (5,2), она придёт из upper
upper[:-1] = [(5,2), (3,4), (1,3)]    ← отрезали (0,0), она уже есть в lower
hull       = [(0,0), (4,0), (5,2), (3,4), (1,3)]
```

Каждая вершина ровно один раз, точки `(2,1)` нет.

`hull` — это вершины многоугольника **в порядке обхода против часовой стрелки**:
направо по низу, вверх по правому краю, налево по верху и назад вниз. Порядок
именно против часовой — прямое следствие того, что мы оставляли только левые
повороты.

Список замкнут в **цикл**: за последней вершиной снова идёт первая, просто в
списке это не записано. Поэтому в калиперах везде стоит `% m` —
`hull[(i + 1) % m]` для последней вершины даёт нулевую.

### Где ломается версия 2

Финальный перебор пар по вершинам оболочки — это O(h²). Обычно h крошечное, но
если точки лежат близко к окружности, внутренних точек почти нет и в оболочку
попадает почти всё множество.

Именно такие тесты в задаче есть — это тесты 26 и 29:

| тест | точек | вершин оболочки | результат `5-2.py` |
|---|---|---|---|
| 26 | 170295 | **84627** | не уложился в 10 с |
| 29 | 175507 | **113446** | не уложился в 10 с |

При 113446 вершинах перебор пар — это больше 6 миллиардов пар, то есть часы.
Так что версия 2 задачу **не сдаёт**, хотя на 28 тестах из 30 выглядит отлично.
Это типичная ловушка: решение кажется рабочим, пока не попадётся специальный
антитест.

## Версия 3: вращающиеся калиперы (`5-3.py`)

Название от штангенциркуля. Представь, что оболочку зажали двумя параллельными
линейками и медленно проворачиваешь их вокруг фигуры на полный оборот. Когда
одна линейка прижата к ребру, вторая касается ровно одной вершины — самой
далёкой от этого ребра. **Самая длинная пара обязательно окажется среди таких
пар «ребро ↔ противоположная вершина»**, поэтому достаточно проверить только их.

```python
best = 0
j = 1
for i in range(m):
    a = hull[i]
    b = hull[(i + 1) % m]
    while cross(a, b, hull[(j + 1) % m]) > cross(a, b, hull[j]):
        j = (j + 1) % m
    c = hull[j]
    best = max(best, dist2(a, c), dist2(b, c))
```

- `a, b` — текущее ребро оболочки, `j` — индекс самой далёкой от него вершины.
- Сравниваются не расстояния, а `cross`: как разобрано выше, расстояние от
  вершины до прямой `a-b` пропорционально `cross(a, b, вершина)`, а основание
  `a-b` у всех вариантов общее. Считать корни и делить не нужно — всё в целых.
- Пока следующая вершина `j+1` дальше текущей `j`, двигаем `j` вперёд.
- Проверяем два расстояния: от найденной вершины `c` до `a` и до `b`.

**Почему это быстро.** Указатель `j` никогда не откатывается назад: когда ребро
проворачивается против часовой стрелки, противоположная вершина тоже едет только
вперёд. За весь цикл `i` обходит оболочку один раз и `j` тоже один раз, итого
O(h), а не O(h²). Это тот же приём, что «два указателя» на массиве, только по
кругу.

### Частные случаи

```python
if m < 3:
    print(dist2(points[0], points[-1]))
    sys.exit()
```

Если **все точки лежат на одной прямой**, многоугольника не существует, оболочка
схлопывается до 2 точек и калиперы работать не могут. Ответ — расстояние между
крайними точками отсортированного списка, то есть между концами отрезка.

Дубликаты убираются на входе через `set`, поэтому случай «все точки одинаковые»
превращается в «одна точка» и даёт 0.

## Что изучить, чтобы разобраться

Порядок от простого к сложному:

1. **Метод двух указателей** на обычных массивах (без геометрии) — там видна
   идея монотонного невозвращающегося указателя, которая потом используется в
   калиперах.
2. **Векторное произведение**: знак поворота, площадь треугольника, площадь
   многоугольника формулой шнурков.
   https://cp-algorithms.com/geometry/basic-geometry.html
   https://cp-algorithms.com/geometry/oriented-triangle-area.html
3. **Выпуклая оболочка**:
   https://ru.algorithmica.org/cs/convex-hulls/ (на русском, самое доступное)
   https://cp-algorithms.com/geometry/convex-hull.html (там же monotone chain)
4. **Вращающиеся калиперы** (rotating calipers) — уже поверх всего этого.

Задачи для практики:
- Timus 1281 «River Basin» — https://acm.timus.ru/problem.aspx?space=1&num=1281
- Codeforces 166B «Polygons» — https://codeforces.com/problemset/problem/166/B
- acmp.ru, раздел «Геометрия», задачи 1–2 уровня сложности

Лучший способ понять построение оболочки: взять лист, поставить 6–7 своих точек,
отсортировать по x и прогнать нижнюю половину руками, рисуя стек после каждого
шага. Момент, когда точка вылетает из стека, — это и есть весь алгоритм.
