# Задача 6. Метролис — минимум смен цвета

Разбор рассчитан на то, что про графы, BFS и Дейкстру ты ещё ничего не знаешь.
Все понятия вводятся по дороге. Решение — один файл `6.py`, 50 строк.

---

## Условие своими словами

Есть станции метро (пронумерованы от 1 до N) и линии между ними. Линия
**односторонняя**: если написано `1 2 r`, то по ней можно ехать из станции 1 в
станцию 2, но не обратно. У каждой линии есть цвет — буква от `a` до `z`.

Ты едешь со станции 1 на станцию N. Пересаживаться можно сколько угодно раз.
Больно только одно: **каждый раз, когда ты пересаживаешься с линии одного цвета
на линию другого цвета, засчитывается один удар**. Ехать дальше тем же цветом
бесплатно, число станций и длина пути вообще никого не волнуют.

Первая линия удара не вызывает: ты только сел, менять было не с чего.

Надо найти минимальное число ударов. Если доехать нельзя — вывести `-1`.

### Пример (тест 1 из папки с тестами)

```
4 4          ← 4 станции, 4 линии
1 2 r        ← из 1 в 2, цвет r
2 3 r
3 4 r
1 3 b
```

```
              r            r            r
        (1) ─────▶ (2) ─────▶ (3) ─────▶ (4)
          \                    ▲
           \        b          │
            └───────────────────┘
```

Два способа доехать до станции 4:

| путь | цвета по порядку | ударов |
|---|---|---|
| 1 → 2 → 3 → 4 | r, r, r | **0** |
| 1 → 3 → 4 | b, r | 1 (пересел с `b` на `r`) |

Правильный ответ — 0. Обрати внимание: выигрывает путь, который **длиннее** по
числу линий. Это главная ловушка задачи, к ней ещё вернёмся.

## Часть 1. Что такое граф

**Граф** — это просто «точки и стрелки между ними». Точки называют
**вершинами**, стрелки — **рёбрами**. В нашей задаче:

- вершина = станция,
- ребро = линия,
- ребро **ориентированное** (со стрелкой), потому что линия односторонняя,
- у ребра есть **метка** — цвет.

Больше в графе ничего нет. Ни координат, ни расстояний — только «из кого в кого
можно перейти». Всё, что нарисовано на картинке выше кружочками и стрелками, —
это и есть граф.

Две вещи, которые в этой задаче явно разрешены и обычно ломают неаккуратный код:

- **петля** — ребро из вершины в саму себя (`4 4 z` в тесте 8). Ехать по ней
  можно, но смысла нет.
- **кратные рёбра** — несколько линий между одной и той же парой станций, в том
  числе разных цветов (`4 6 g` и `4 6 s` в тесте 5).

## Часть 2. Как хранить граф в программе

### Почему не таблица

Первое, что приходит в голову, — таблица N×N: в клетке `[u][v]` написано, есть
ли линия. Для N = 200000 такая таблица — это 4·10¹⁰ клеток. Не влезет ни в
какую память, и уже поэтому так не делают.

### Список смежности

Хранят по-другому: для каждой вершины — **список тех, куда из неё можно
попасть**. Это называется **список смежности**.

```python
adj = [[] for _ in range(n + 1)]
```

`adj[u]` — список линий, выходящих из станции `u`. Каждая линия записана парой
`(куда, цвет)`.

Почему `n + 1`, а не `n`: станции нумеруются с 1, а списки в питоне — с 0. Проще
завести один лишний элемент `adj[0]` и не трогать его, чем всюду писать `u - 1`
и путаться.

Почему `[[] for _ in range(n + 1)]`, а не `[[]] * (n + 1)`: вторая запись создаёт
**один** список и кладёт ссылку на него `n+1` раз — добавив линию одной станции,
ты добавишь её всем сразу. Классическая ошибка.

Для теста 1 получится:

```
adj[1] = [(2, r), (3, b)]
adj[2] = [(3, r)]
adj[3] = [(4, r)]
adj[4] = []
```

### Чтение входных данных

```python
data = sys.stdin.buffer.read().split()
```

Читает **весь** ввод одним куском и режет по пробелам и переводам строк. Для
200000 строк это в разы быстрее, чем читать построчно через `input()`. На выходе
получается список «слов», но не обычных строк, а `bytes` — сырых байтов.

```python
n = int(data[0])
m = int(data[1])
pos = 2                            # первые два слова уже разобрали
for _ in range(m):
    u = int(data[pos])
    v = int(data[pos + 1])
    c = data[pos + 2][0] - 97
    pos += 3
    adj[u].append((v, c))
```

Каждая линия занимает во входе ровно 3 слова, поэтому `pos` шагает по 3.

Отдельно про строчку с цветом:

```python
c = data[pos + 2][0] - 97
```

- `data[pos + 2]` — это цвет, но в виде `bytes`, например `b'r'`;
- взятие `[0]` у `bytes` даёт **число** — код символа. У `b'r'` это 114;
- 97 — код буквы `a`.

Итого `'a'` превращается в 0, `'b'` в 1, ..., `'z'` в 25. Цвет становится
маленьким числом, а числа сравнивать и хранить быстрее и удобнее, чем строки.

## Часть 3. Что такое обход в ширину (BFS)

Прежде чем решать нашу задачу, разберём более простую и очень известную:
**за какое минимальное число рёбер можно дойти из вершины 1 в вершину N?**
Её решает **обход в ширину**, по-английски breadth-first search, сокращённо
**BFS**.

Идея — расходящаяся волна.

```
       ┌──▶ (2) ──┐
  (1) ─┤          ├──▶ (3)
       └──▶ (4) ──┘
```

- **Волна 0:** только сама вершина 1. Ноль шагов.
- **Волна 1:** всё, куда можно попасть из вершины 1 за один шаг — это 2 и 4.
- **Волна 2:** всё, куда можно попасть из вершин волны 1 и где мы ещё не были —
  это 3.

Как только вершина попала в волну номер `k`, ответ для неё — `k`, и лучше уже не
будет: если бы существовал путь короче, эта вершина попала бы в более раннюю
волну.

В коде волны не хранят отдельно. Вместо этого заводят **очередь** — список, из
которого берут с начала, а кладут в конец (как очередь в магазине: кто раньше
встал, того раньше обслужат). Плюс отметки «здесь уже были», чтобы не ходить
кругами.

```python
очередь = [1]
пока очередь не пуста:
    v = взять первый элемент очереди
    для каждого ребра v -> to:
        если в to ещё не были:
            отметить to
            положить to в конец очереди
```

Очередь сама раскладывает вершины по волнам: пока не кончились вершины волны 1,
до волны 2 дело не дойдёт.

**Главное, что нужно запомнить: BFS даёт кратчайший путь только тогда, когда все
шаги стоят одинаково.** Он считает шаги, а не стоимость.

## Часть 4. Почему в нашей задаче BFS не годится

В задаче про Метролис шаги стоят **по-разному**: переход по линии того же цвета
стоит 0 ударов, а по линии другого цвета — 1 удар.

Вернись к тесту 1. BFS честно скажет: «до станции 4 можно за 2 линии — через
станцию 3 по синей и красной». По числу линий он прав. Но по числу ударов этот
путь хуже, чем длинный красный путь через 2 и 3, который стоит 0.

Значит нужен алгоритм, который умеет работать с **разной ценой шагов**. Он
называется алгоритмом Дейкстры.

---

## Часть 5. Алгоритм Дейкстры

### Идея

BFS — волна, которая расходится **по числу шагов**. Дейкстра — волна, которая
расходится **по накопленной цене**. Правило одно:

> Всегда обрабатывай ту вершину, до которой на данный момент известен самый
> дешёвый путь.

Почему это правильно, если все цены неотрицательные: пусть самая дешёвая
известная вершина стоит `d`. Подешеветь она уже не может — любой другой путь до
неё пойдёт через какую-то ещё не обработанную вершину, а та стоит не меньше `d`,
и к ней придётся ещё что-то прибавить. Значит `d` — окончательный ответ для этой
вершины, и её можно спокойно обрабатывать.

Именно поэтому в коде можно сразу печатать ответ, как только из очереди достали
станцию N: раз её достали, её цена уже окончательная.

### Куча

Остался вопрос: как быстро находить «самую дешёвую известную вершину»? Искать
минимум перебором по всему списку — долго. Для этого есть структура данных
**куча** (heap), она же **очередь с приоритетом**.

Куча — это ящик, в который можно:

- положить элемент — `heapq.heappush(heap, x)`;
- достать **самый маленький** элемент — `heapq.heappop(heap)`.

Обе операции быстрые (порядка log от числа элементов): куча не хранит всё
отсортированным, она поддерживает более слабый порядок, но его хватает, чтобы
минимум всегда лежал сверху. Внутри это дерево в массиве; для решения задач
внутренности знать не обязательно, достаточно понимать контракт «клади что
угодно, забирай минимум».

В питоне куча — это обычный список плюс функции модуля `heapq`, которые его
поддерживают в правильном порядке. **Свой список так трогать нельзя** — только
через `heappush` / `heappop`.

Кладут в кучу **кортежи**, и первым элементом всегда идёт то, по чему сортируем
(у нас — цена):

```python
heapq.heappush(heap, (0, v, c))     # (цена, станция, цвет)
```

Кортежи сравниваются по первому элементу, при равенстве — по второму и так
далее, поэтому «минимальный кортеж» = «минимальная цена».

### Ленивое удаление

Неприятность: в куче нельзя найти уже лежащий элемент и уменьшить ему цену.
Поэтому делают проще — кладут ещё одну запись с новой ценой, а старая остаётся
мусором. Когда мусорная запись всплывёт, её узнают и выбросят:

```python
d, v, c = heapq.heappop(heap)
if d > dist.get((v, c), INF):    # для этого состояния уже нашли путь дешевле
    continue                     # значит эта запись устарела
```

Приём называется **ленивым удалением** и встречается в любой реализации Дейкстры
на питоне. Просто прими его как часть шаблона.

## Часть 6. Главная идея задачи: состояние — это станция И цвет

Теперь самое важное. Обычная Дейкстра хранит «цену дойти до вершины `v`». Здесь
так не получится, и вот почему.

```
              r            r            r
        (1) ─────▶ (2) ─────▶ (3) ─────▶ (4)
          \                    ▲
           \        b          │
            └───────────────────┘
```

Посмотри на станцию 3. В неё можно приехать двумя способами:

- по красной линии из станции 2 — заплатив 0 ударов;
- по синей линии прямо из станции 1 — тоже заплатив 0 ударов (первая линия
  бесплатна).

Цена одинаковая, но ситуации **разные**! Дальше из станции 3 идёт красная линия.
Тому, кто приехал красным, она достанется бесплатно. Тому, кто приехал синим, —
за 1 удар.

Вывод: пометки «станция 3, цена 0» недостаточно, она теряет важное. Нужно
помнить ещё и то, **каким цветом ты сейчас едешь**:

> `dist[(v, c)]` = минимальное число ударов, чтобы оказаться на станции `v`,
> приехав в неё линией цвета `c`.

Такая пара «где я + что про меня ещё важно» называется **состоянием**. Приём
общий: если алгоритм на вершинах не работает, потому что важна ещё какая-то
деталь, вершины «размножают» по этой детали. В других задачах вместо цвета
бывает остаток от деления, число оставшихся денег, направление движения — идея
та же.

### Переход между состояниями

Стою в состоянии `(v, c)` с ценой `d`. Беру линию `v → to` цвета `c2`:

```
цена нового состояния (to, c2) = d,      если c2 == c   (еду тем же цветом)
                                 d + 1,  если c2 != c   (пересел — удар)
```

### Старт

«Цвет первой линии удара не вызывает» переводится так: **все состояния, в
которые можно попасть по линии из станции 1, стоят 0**.

```python
for (v, c) in adj[1]:
    dist[(v, c)] = 0
    heapq.heappush(heap, (0, v, c))
```

### Финиш

Ответ — первое извлечённое из кучи состояние вида `(N, любой цвет)`. Куча отдаёт
состояния по возрастанию цены, поэтому первое же и есть минимум.

Если куча опустела, а такое состояние не встретилось, — до станции N не добраться,
ответ `-1`.

### Сколько всего состояний

Состояние `(v, c)` появляется только тогда, когда в `v` реально входит линия
цвета `c`. Каждая линия порождает ровно одно состояние, значит состояний не
больше M — не больше 200000. Хранить их в обычном списке размера 26·N было бы
расточительно, поэтому `dist` — **словарь**: в нём лежат только те состояния,
которые действительно встретились.

Отсюда же и `dist.get((v, c), INF)` вместо `dist[(v, c)]`: у ещё не встреченного
состояния ключа в словаре нет, и `get` вернёт «бесконечность» вместо ошибки.

## Часть 7. Разбор кода `6.py` по кускам

```python
data = sys.stdin.buffer.read().split()
n = int(data[0])
m = int(data[1])
```

Прочитали весь ввод, взяли число станций и число линий.

```python
adj = [[] for _ in range(n + 1)]
pos = 2
for _ in range(m):
    u = int(data[pos])
    v = int(data[pos + 1])
    c = data[pos + 2][0] - 97
    pos += 3
    adj[u].append((v, c))
```

Построили список смежности (разобран в части 2).

```python
if n == 1:
    print(0)
    sys.exit()
```

Отдельный случай: старт и финиш — одна и та же станция, ехать вообще не надо,
ответ 0. Без этой проверки алгоритм начал бы искать путь и на тесте 9 выдал бы
`-1`. Это самая частая ошибка в задаче.

```python
INF = 1 << 30
dist = {}
heap = []
```

`1 << 30` — это 2³⁰, примерно миллиард: заведомо больше любого ответа (ударов не
может быть больше числа линий, то есть 200000). Такое «бесконечно большое»
значение удобно как заглушка для ещё не найденных состояний.

```python
for (v, c) in adj[1]:
    if dist.get((v, c), INF) > 0:
        dist[(v, c)] = 0
        heapq.heappush(heap, (0, v, c))
```

Стартовые состояния. Проверка `> 0` нужна на случай кратных линий: если из
станции 1 в станцию 2 идут две красные линии, состояние `(2, r)` не нужно
класть в кучу дважды.

```python
while heap:
    d, v, c = heapq.heappop(heap)
    if d > dist.get((v, c), INF):
        continue
```

Достаём самое дешёвое состояние и выбрасываем устаревшие записи (ленивое
удаление из части 5).

```python
    if v == n:
        print(d)
        sys.exit()
```

Дошли до финиша. Раз состояние извлечено из кучи — его цена окончательная,
можно печатать и выходить.

```python
    for (to, c2) in adj[v]:
        nd = d if c2 == c else d + 1
        if nd < dist.get((to, c2), INF):
            dist[(to, c2)] = nd
            heapq.heappush(heap, (nd, to, c2))
```

Пробуем все линии, выходящие из текущей станции. Считаем цену нового состояния и
кладём в кучу, только если стало лучше, чем было известно раньше. Проверка
`nd < dist.get(...)` — это то, что не даёт алгоритму ходить по кругу
бесконечно: цена состояния может только уменьшаться, а уменьшаться бесконечно
она не может.

```python
print(-1)
```

Куча опустела, финиш не встретился — пути нет.

## Часть 8. Трассировка

### Тест 2 — простой

```
3 2
1 2 a
2 3 b
```

```
adj[1] = [(2, a)]
adj[2] = [(3, b)]
adj[3] = []

старт: (2,a) = 0, куча [(0, 2, a)]

достали (0, 2, a) : станция 2, это не финиш
                    линия 2→3 цвета b, цвет другой -> (3,b) = 0 + 1 = 1
                    куча [(1, 3, b)]
достали (1, 3, b) : станция 3 — это финиш N -> печатаем 1
```

Ответ 1: одна пересадка с `a` на `b`.

### Тест 5 — посложнее

```
7 12
4 6 g     1 4 u     1 5 b     3 2 w
7 2 t     3 7 n     4 6 s     5 2 s
2 7 s     2 2 y     4 3 r     1 6 b
```

Списки смежности:

```
adj[1] = [(4,u), (5,b), (6,b)]
adj[2] = [(7,s), (2,y)]
adj[3] = [(2,w), (7,n)]
adj[4] = [(6,g), (6,s), (3,r)]
adj[5] = [(2,s)]
adj[7] = [(2,t)]
```

Стартовых состояний три, все стоят 0: `(4,u)`, `(5,b)`, `(6,b)`.

Дальше куча отдаёт сначала всё, что стоит 0, потом всё, что стоит 1. Полезная
цепочка получается такая:

```
(5,b) = 0     приехали на станцию 5 синей линией
   │
   │ линия 5→2 цвета s, цвет сменился -> +1
   ▼
(2,s) = 1     приехали на станцию 2 линией цвета s
   │
   │ линия 2→7 цвета s, цвет тот же -> +0
   ▼
(7,s) = 1     станция 7 — это финиш
```

Ответ 1. Маршрут: `1 →b 5 →s 2 →s 7`, одна пересадка (с `b` на `s`), дальше
едем цветом `s` бесплатно.

Для сравнения, путь `1 →u 4 →r 3 →n 7` стоит 2 удара: `u → r` и `r → n`. Он
такой же длины по числу линий, но дороже — Дейкстра его не выберет.

## Часть 9. Частные случаи

| случай | пример | что происходит |
|---|---|---|
| N = 1 | тест 9 | отдельная проверка `if n == 1: print(0)` — иначе неверный ответ |
| пути нет | тест 3 | куча опустела, ничего не напечатали → `print(-1)` |
| M = 0 | — | `adj[1]` пуст, стартовых состояний нет, куча пуста сразу → `-1` |
| петля `u → u` | тест 8 (`4 4 z`) | обычное ребро; цену не улучшает, поэтому в кучу второй раз не попадёт |
| кратные линии | тест 5 (`4 6 g`, `4 6 s`) | обычные рёбра, обе лежат в `adj[4]` и обе рассматриваются |

## Часть 11. Сколько это работает

Состояний не больше M. Из каждого состояния `(v, c)` перебираются все линии,
выходящие из `v`. Если в станцию входят линии `k` разных цветов, её линии
просматриваются `k` раз, а цветов всего 26 — значит работы не больше чем
`26 · M` просмотров плюс работа кучи.

Формально это O(26 · M · log M). Звучит страшновато, но множитель 26 — оценка
сверху для самого злого случая; в тестах этой задачи из станции почти всегда
выходит одна-две линии, поэтому реально всё летает: 0.23 секунды при лимите
задачи в несколько секунд.

### Если захочется быстрее

Два известных улучшения — их полезно знать, но для этой задачи они не нужны:

1. **0-1 BFS.** Когда цены рёбер бывают только 0 и 1, куча не нужна: хватает
   двусторонней очереди (`collections.deque`), где переходы ценой 0 кладут
   в начало, а ценой 1 — в конец. Порядок извлечения остаётся правильным, а
   каждая операция стоит O(1) вместо O(log). Убирает логарифм.
   Читать: https://cp-algorithms.com/graph/01_bfs.html
2. **Отдельный «вершинный» узел на станцию.** Чтобы не платить множитель 26,
   для каждой станции заводят дополнительный узел «стою здесь и готов сменить
   цвет»: все цвета входят в него бесплатно, а выходят из него за 1 удар. Тогда
   пересадка описывается `k + k` рёбрами вместо `k · d`, и всё решение
   становится честно линейным, O(N + M).
